# hook 注入以使用者自訂的比對規則歸屬 plugin

shell hook（例如 SessionStart、UserPromptSubmit）注入的 context，引擎只提供事件名稱，不提供是哪個 plugin 注入的。我們不自動猜測來源，改由使用者在設定裡寫「開頭文字=名稱」的比對規則。每段注入只拿第一行比對，比完就丟；主對話裡沒比中的只算一個合計，subagent 裡的依事件分列。預設不附任何規則。

## Considered Options

- **依內容自動猜測**：會猜錯，還得保留注入內容來比對，違反「內容算完 token 就丟」的界線。
- **讀各 plugin 的 hooks 設定來對應**：要動用檔案存取，而且同一事件掛了好幾個 hook 時還是對不準。
- **只標事件、不歸屬 plugin**：做法正確，但認不出 ponytail、caveman 這類每輪注入的來源，達不到這個 mod 的目的。原本是比不中規則時的顯示方式（事件名稱加序號），但使用者看不出每一列是什麼，改成只列合計。

## Consequences

- 規則存在使用者的 settings.json 裡，plugin 更新不會清掉，但移除 plugin 時會一起刪除。設定欄位的名稱和格式因此算是對外介面，不相容的修改要升 major 版號，並在 README 說明怎麼搬移舊設定。
- 其他 plugin 改了注入內容的開頭，規則就會失準，要由使用者自己更新。
